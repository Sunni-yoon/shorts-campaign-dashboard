# 숏폼 캠페인 성과 리포트 대시보드

키워드(=캠페인 주제)별 YouTube 쇼츠 성과를 수집해 지표로 만들고, 브랜드가 의사결정에 쓸 수 있는 대시보드로 보여 주는 프로젝트입니다.

**대시보드:** https://shorts-campaign-dashboard-fiegkrrdeazp5sdzj3gbxm.streamlit.app/

대시보드는 결정 질문 순서로 구성되어 있습니다.

1. **우리 캠페인 기준선은?** 조회수·조회수 속도·참여율·구독자 대비 조회수의 중앙값
2. **어떤 주제가 잘 퍼지나?** 키워드별 평균·중앙값 요약표
   - **어떤 포맷이 잘 퍼지나?** LLM으로 분류한 콘텐츠 포맷별 성과, 키워드 × 포맷 표
   - **반응은 좋았나?** 댓글 감성(긍정·부정·중립)과 구매의향 비율, 키워드별·포맷별
3. **어떤 크리에이터와 일할까?** 채널 단위 집계, 구독자 수 범위 필터
4. **무엇을 참고해 만들까?** 지표별 상위 영상과 YouTube 링크
5. **세부 분포** 키워드별 참여율 분포, 조회수 vs 참여율

섹션별 관찰 문장(숫자로 확인되는 사실 한 줄)은 `observations.py`에서 생성합니다. 대시보드 화면에서는 현재 꺼 두었고, `config.py`의 `SHOW_OBSERVATIONS = True`로 다시 켤 수 있습니다.

## 데이터 수집 방식

분석 키워드: `buldak challenge`, `spicy noodle challenge`, `shin ramyun`, `korean ramen recipe` (미국 지역, 영어 기준)

- 데이터는 저장소에 포함하지 않습니다. 배포된 대시보드(Streamlit 앱)가 YouTube Data API v3로 직접 수집합니다.
- 대시보드를 열었을 때 데이터가 없거나 마지막 수집 후 24시간이 지났으면 새로 검색합니다. 아무도 열지 않으면 수집하지 않습니다.
- 수집 후 30일이 지난 데이터는 자동으로 삭제합니다 (YouTube API 정책의 30일 갱신·삭제 기준).
- 수집 기준 (코드상 이름 `v2_relevance_3to30d`)
  - 관련도순 검색, 수집 시점 기준 3~30일 전에 업로드된 영상
  - 키워드당 쇼츠 최대 50개 (검색 결과 최대 2페이지)
  - 대시보드는 가장 최근에 성공한 수집 1회분만 사용
  - 처음에는 최신순으로 수집했지만, 업로드 1일 미만 영상이 너무 많아 이 기준으로 바꿨습니다(아래 분석 결과 요약 참고).
- 1회 수집에 약 700~820 API 유닛이 듭니다 (하루 한도 10,000).

## 지표 정의

| 지표 | 계산 | 제외 기준 |
|---|---|---|
| 조회수 | 영상별 가장 최근 스냅샷의 조회수 | 없음 |
| 조회수 속도 | 조회수 ÷ 업로드 후 경과 일수 | 경과 일수는 최소 1일로 처리 |
| 참여율 | (좋아요 + 댓글) ÷ 조회수 | 좋아요 숨김·댓글 사용 중지 영상은 0으로 넣지 않고 제외 |
| 구독자 대비 조회수 | 조회수 ÷ 채널 구독자 수 | 구독자 비공개 채널 제외. 같은 수집 시점(없으면 가장 가까운 시점)의 구독자 수 사용 |
| 긍정·부정 비율 | 영상별 분석 댓글 중 긍정(부정)으로 분류된 댓글 비율 | 분석 댓글이 5개 미만인 영상 제외 |
| 구매의향 비율 | 영상별 분석 댓글 중 "어디서 사요?", "먹어 보고 싶다"처럼 사거나 먹어 보고 싶다는 표현이 있는 댓글 비율 | 분석 댓글이 5개 미만인 영상 제외 |

- 공유 수는 API가 제공하지 않아 참여율에 포함하지 않습니다.
- 모든 지표는 영상별로 계산한 뒤 키워드·포맷별로 평균(영상별 값의 단순 평균)과 중앙값을 냅니다. 쇼츠는 일부 영상의 조회수가 크게 튀어 평균이 중앙값보다 훨씬 커지므로, 중앙값을 기준으로 봅니다.
- 구매의향 비율은 대부분 영상이 0%라 중앙값도 0%에 가깝습니다. 그래서 구매의향은 평균으로 비교합니다.

### 쇼츠 판정 기준

YouTube API에는 쇼츠 여부 필드가 없어서, YouTube 공식 기준을 길이와 화면 비율로 적용합니다.

- 정사각형 또는 세로 영상(높이 ≥ 너비)만 쇼츠입니다. 가로 영상은 길이와 상관없이 일반 영상입니다.
- 2024-10-15 이후 업로드: 180초 이하
- 2024-10-15 이전 업로드: 60초 이하
- 화면 비율은 `videos.list`의 `player.embedWidth/embedHeight`로 판단합니다.

### 콘텐츠 포맷 분류 (OpenAI)

영상의 제목·설명·해시태그를 바탕으로 포맷 하나를 고릅니다.

- 포맷: 챌린지 / 레시피·조리 / 먹방·ASMR·맛평가 / 기타
- 겹치면 위의 규칙이 우선합니다.
  1. 제목에 도전 구조(challenge, vs, 상금, 몇 입에)가 있으면 챌린지
  2. 만드는 과정이 중심이면 레시피·조리
  3. 먹거나 맛을 평가하는 영상이면 먹방·ASMR·맛평가
  4. 어디에도 안 맞으면 기타
- ASMR은 포맷이 아니라 연출 방식이라 독립 분류로 두지 않습니다.
- 코미디·상황극은 LLM 분류와 사람 확인 모두에서 해당 영상이 없어 목록에서 뺐습니다.
- 출력은 JSON 스키마로 강제합니다(포맷, 확신도, 근거 한 줄). 모델·프롬프트 버전·분류 시각을 함께 저장합니다.
- 같은 프롬프트 버전으로 이미 분류한 영상은 다시 분류하지 않습니다.
- 정확도 검증은 하지 않습니다. 사람이 50개를 직접 라벨링해 보니 약 15개(30%)는 한 영상에 여러 포맷이 섞여 있어 단일 포맷으로 정하기 어려웠습니다. 단일 포맷 분류의 정확도를 정의하기 어려워 LLM 분류 결과를 그대로 쓰며, 개선하려면 다중 라벨이 필요합니다.
- 경계 사례도 많습니다. 프롬프트를 v1에서 v2로 바꿔 다시 분류했더니 184개 중 10개(5.4%)의 포맷이 바뀌었습니다. v1에서 코미디·상황극으로 분류된 영상은 0개였으므로, 이 차이는 프롬프트 문구 변경만으로 생긴 것입니다.
- 기타 비율이 15%를 넘으면 포맷 목록을 다시 검토합니다.

### 댓글 반응 분석 (YouTube + OpenAI)

- 영상별 관련도 상위 댓글 최대 20개를 수집합니다(답글 제외, 영상당 1 API 유닛).
- 댓글 텍스트와 좋아요 수만 저장합니다. 작성자 정보는 저장하지 않고, 댓글 ID는 해시로, 본문의 @멘션은 `@user`로 바꿉니다.
- 댓글 하나씩 독립적으로 분류합니다.
  - 감성: 긍정 / 부정 / 중립
  - 구매의향: 있음 / 없음
- 영상별 비율을 먼저 구한 뒤 키워드·포맷별 평균과 중앙값을 냅니다. 분석 댓글이 5개 미만인 영상은 제외하고, 제외한 수를 표시합니다.
- 대시보드에는 집계 수치만 보여 주고 댓글 원문은 표시하지 않습니다.

### 5. 관찰 사실과 해석

**관찰 사실** (데이터에서 숫자로 확인됨)
- 조회수 중앙값은 buldak challenge가 428,692로 가장 높습니다. 다른 키워드의 7~20배입니다.
- 구독자 대비 조회수 중앙값은 korean ramen recipe(18.42)와 레시피·조리 포맷(13.81)이 가장 높습니다.
- 챌린지 포맷은 조회수 중앙값이 가장 높지만(기타 제외), 댓글 긍정 비율 중앙값은 45.0%로 가장 낮습니다.
- 구매의향 비율 평균은 레시피·조리(6.4%)와 먹방·ASMR·맛평가(5.2%)가 챌린지(1.2%)보다 높습니다.
- buldak challenge는 부정 비율 중앙값이 15.4%로 가장 높습니다. 다만 직접 검토한 부정 댓글 20개 중 제품에 대한 것은 2개였습니다.

**해석 (검증하지 않은 가설)**
- 레시피 영상은 구독자가 적은 채널에서도 구독자 범위를 넘어 퍼지는 경향이 있을 수 있습니다. 그렇다면 작은 크리에이터와 협업할 후보 포맷입니다.
- 챌린지 영상은 도달이 크지만, 반응이 제품보다 출연자와 연출에 쏠릴 수 있습니다. 낮은 긍정 비율이 제품 평가를 뜻하지는 않을 가능성이 큽니다.
- 조리·시식 장면이 있는 영상은 시청자가 제품을 직접 떠올리게 해서 구매의향 표현이 더 나올 수 있습니다.

**인과로 해석할 수 없는 이유**
- **키워드와 포맷이 크게 겹칩니다.** buldak challenge는 50개 중 44개, spicy noodle challenge는 43개가 챌린지입니다. korean ramen recipe는 41개가 레시피·조리입니다. 그래서 위 차이가 키워드(제품·주제) 때문인지 포맷 때문인지 나눌 수 없습니다.
- 표본은 검색 관련도 상위 영상이라 무작위가 아닙니다. 한 시점의 스냅샷이며 광고 조회수가 섞여 있을 수 있습니다.
- 위 해석은 포맷이나 키워드가 성과를 *만든다*는 근거가 아닙니다. 확인하려면 같은 키워드 안에서 포맷을 비교하거나 실험을 해야 합니다.

## 한계

- **댓글은 관련도 상위 20개만 분석합니다.** 댓글 작성자는 시청자 일부라 전체 반응을 대표하지 않고, 긍정 댓글이 실제 구매로 이어지는지는 알 수 없습니다.
- **댓글 감성은 대상을 구분하지 않습니다.** 감성은 댓글 전체의 분위기 기준이라 제품·출연자·연출 중 무엇에 대한 반응인지 나누지 않습니다. buldak challenge의 부정 댓글 20개를 직접 확인해 보니 제품에 대한 부정은 2개뿐이었고, 나머지는 출연자 놀림, 매운맛 리액션, 영상 진정성 의심, 밈이었습니다. 감성 분석을 브랜드 판단에 쓰려면 감성의 대상(제품·출연자·연출)을 구분해야 합니다.

- **포맷은 제목·설명 기반 LLM 분류입니다.** 정확도 검증을 하지 않았고(위 참고), 실제 영상 내용과 다를 수 있습니다.

- **무작위 표본이 아닙니다.** 키워드 검색의 관련도 상위 영상이라 성과가 좋은 영상 쪽으로 치우쳐 있을 수 있습니다.
- **공유 수·시청 시간·비용·전환은 포함하지 않습니다.** YouTube Data API가 제공하지 않습니다.
- **광고 조회수와 자연 조회수를 구분할 수 없습니다.**
- **구독자 수는 반올림된 값입니다.** YouTube가 유효숫자 3자리로 반올림해 제공합니다.
- **구독자가 매우 적은 채널은 구독자 대비 조회수가 극단적으로 커집니다.** 그래서 크리에이터 표는 기본으로 구독자 1,000명 이상만 보여 줍니다.
- **크리에이터 표의 영상 수는 이번 검색에 잡힌 영상 수입니다.** 채널 전체 영상 수가 아닙니다.
- **쇼츠 판정은 근사치입니다.** 길이·비율 조건을 만족하지만 일반 영상으로 올라온 경우를 구분하지 못합니다.

## 실행 방법

Python 3.10 이상에서 실행합니다.

```bash
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt     # macOS/Linux: venv/bin/python
```

프로젝트 폴더에 `.env` 파일을 만들고 API 키를 넣습니다. 이 파일은 git에서 제외됩니다. OpenAI 키가 없으면 포맷 분류만 건너뜁니다.

```
YOUTUBE_API_KEY=발급받은_키
OPENAI_API_KEY=발급받은_키
```

```bash
venv\Scripts\python.exe -m streamlit run dashboard.py   # 대시보드 (데이터가 없으면 열 때 자동 수집)
venv\Scripts\python.exe collect.py search               # 명령줄에서 직접 수집
venv\Scripts\python.exe collect.py refresh              # 저장된 쇼츠의 지표만 갱신 (약 10유닛)
venv\Scripts\python.exe collect.py purge                # 30일 지난 데이터 삭제
venv\Scripts\python.exe classify_formats.py             # 미분류 쇼츠의 포맷 분류 (OpenAI)
venv\Scripts\python.exe collect_comments.py             # 새 영상의 상위 댓글 수집 (영상당 1유닛)
venv\Scripts\python.exe classify_comments.py            # 새 댓글의 감성·구매의향 분류 (OpenAI)
venv\Scripts\python.exe -m pytest tests                 # 테스트
```

- 로컬에서 자동 수집을 끄려면 환경변수 `AUTO_COLLECT=0`을 설정합니다.
- API 키를 읽는 순서는 환경변수(`.env` 포함), 그다음 Streamlit Secrets입니다. 키 값은 화면이나 로그에 출력하지 않고, 오류 메시지에 섞이면 `***`로 가립니다.

### Streamlit Community Cloud 배포

1. 이 저장소로 새 앱을 만들고 Main file을 `dashboard.py`로 지정합니다.
2. Advanced settings → Secrets에 다음을 입력합니다.
   ```toml
   YOUTUBE_API_KEY = "발급받은_키"
   OPENAI_API_KEY = "발급받은_키"
   ```
3. Google Cloud Console에서 이 키의 API 제한을 YouTube Data API v3로만 설정하기를 권장합니다.

## 폴더 구조

```
├── dashboard.py        # Streamlit 대시보드 (화면만, 계산은 metrics.py)
├── metrics.py          # 지표 계산·요약·제외 집계 (대시보드·리포트 공용)
├── observations.py     # 섹션별 관찰 문장 생성 (숫자 사실만, 화면 표시는 SHOW_OBSERVATIONS로 제어)
├── auto_collect.py     # 앱을 열 때 24시간 경과 확인 → 수집, 동시 접속 잠금, 실패 후 재시도 대기
├── collect.py          # YouTube API 수집 (search / refresh / reclassify / purge)
├── classify_formats.py # 콘텐츠 포맷 LLM 분류 (OpenAI, 미분류 영상만)
├── collect_comments.py # 영상별 상위 댓글 수집 (개인 식별 정보 저장 안 함)
├── classify_comments.py  # 댓글 감성·구매의향 LLM 분류 (댓글 하나씩)
├── format_eval.py      # (보류) 라벨링 표본 내보내기·정확도 계산 — 다중 라벨 도입 시 재사용
├── db.py               # SQLite 스키마·저장·30일 삭제
├── keys.py             # API 키 읽기 (.env → Streamlit Secrets), 키 가리기
├── config.py           # 키워드·수집 기준·판정 기준·보관 기간 설정
├── tests/              # pytest (지표 계산, 관찰 문장, 자동 수집·삭제 로직)
├── requirements.txt
└── data/               # SQLite DB (git 제외, 실행 시 생성)
```
