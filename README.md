# 숏폼 캠페인 성과 리포트 대시보드

불닭 YouTube 쇼츠를 포맷(챌린지 · 레시피 · 먹방)별로 나눠 성과와 시청자 반응을 비교하는 대시보드입니다. 질문은 "**불닭 쇼츠 중 어떤 포맷이 가장 잘 퍼지고 반응이 좋은가**"입니다.

**대시보드:** https://shorts-campaign-dashboard-fiegkrrdeazp5sdzj3gbxm.streamlit.app/

대시보드는 결정 질문 순서로 구성되어 있습니다.

1. **전체 기준선은?** 영상 수와 조회수·조회수 속도·참여율·구독자 대비 조회수의 중앙값
2. **어떤 포맷이 잘 퍼지나?** 포맷 비교 그래프(지표 4개, 막대에 마우스를 올리면 95% 신뢰구간 표시), 포맷별 평균·중앙값 요약표
3. **포맷별 반응은 좋았나?** 포맷별 감성 구성(긍정·중립·부정) 그래프, 포맷별 댓글 반응표
4. **어떤 크리에이터와 일할까?** 채널 구독자 수 vs 영상 조회수 산점도, 채널 단위 집계(주력 포맷, 구독자 수 범위·주력 포맷 필터)
5. **포맷별로 무엇을 참고해 만들까?** 포맷별·지표별 상위 영상과 YouTube 링크, 경계 사례 표시
6. **세부 분포** 포맷별 참여율 분포, 조회수 vs 참여율
7. **데이터 기준 · 해석 주의** 수집 기준, 지표 정의, 제외 영상 수, 기타 구성, 포맷 분류 일치율

섹션별 관찰 문장(숫자로 확인되는 사실 한 줄)은 `observations.py`에서 생성합니다. 대시보드 화면에서는 현재 꺼 두었고, `config.py`의 `SHOW_OBSERVATIONS = True`로 다시 켤 수 있습니다.

## 데이터 수집 방식

분석 키워드: `buldak` (미국 지역, 영어 기준)

처음에는 키워드 4개(`buldak challenge`, `spicy noodle challenge`, `shin ramyun`, `korean ramen recipe`)를 비교했습니다. 그런데 키워드마다 제품이 달라서, 차이가 포맷 때문인지 제품 때문인지 나눌 수 없었습니다. 그래서 키워드를 `buldak` 하나로 바꾸고, 같은 브랜드 안에서 포맷끼리 비교하도록 다시 설계했습니다.

- 배포 앱은 2026-11-26 수집 스냅샷을 보여 줍니다. 스냅샷은 비공개 저장소에 두고, 수집 후 30일이 지나면 표시하지 않습니다 (YouTube API 정책의 30일 갱신·삭제 기준). 배포 앱은 자동 수집·분류를 하지 않습니다.
- 데이터는 이 저장소에 포함하지 않습니다. 수집은 로컬에서 YouTube Data API v3로 합니다. 로컬에서는 대시보드를 열었을 때 데이터가 없거나 마지막 수집 후 24시간이 지났으면 새로 검색하고, 수집 후 30일이 지난 데이터는 자동으로 삭제합니다.
- 수집 기준 (코드상 이름 `v3_buldak_3to30d`)
  - 관련도순 검색, 수집 시점 기준 3~30일 전에 업로드된 영상
  - 쇼츠 최대 200개 (검색 결과 최대 6페이지)
  - 대시보드는 가장 최근에 성공한 수집 1회분만 사용
- 1회 수집(검색·영상 정보·채널 구독자 수)에 약 610 API 유닛이 듭니다. 새 영상의 댓글 수집에는 영상당 1유닛이 더 들어, 첫 수집 기준 합계는 약 770유닛입니다 (하루 한도 10,000).

## 지표 정의

| 지표 | 계산 | 제외 기준 |
|---|---|---|
| 조회수 | 영상별 가장 최근 스냅샷의 조회수 | 없음 |
| 조회수 속도 | 조회수 ÷ 업로드 후 경과 일수 | 경과 일수는 최소 1일로 처리 |
| 참여율 | (좋아요 + 댓글) ÷ 조회수 | 좋아요 숨김·댓글 사용 중지 영상은 0으로 넣지 않고 제외 |
| 구독자 대비 조회수 | 조회수 ÷ 채널 구독자 수 | 구독자 1,000명 미만·비공개 채널 제외. 같은 수집 시점(없으면 가장 가까운 시점)의 구독자 수 사용 |
| 긍정·부정 비율 | 영상별 분석 댓글 중 긍정(부정)으로 분류된 댓글 비율 | 분석 댓글이 5개 미만인 영상 제외 |
| 구매의향 비율 | 영상별 분석 댓글 중 "어디서 사요?", "먹어 보고 싶다"처럼 사거나 먹어 보고 싶다는 표현이 있는 댓글 비율 | 분석 댓글이 5개 미만인 영상 제외 |

- 공유 수는 API가 제공하지 않아 참여율에 포함하지 않습니다.
- 모든 지표는 영상별로 계산한 뒤 포맷별로 평균(영상별 값의 단순 평균)과 중앙값을 냅니다. 쇼츠는 일부 영상의 조회수가 크게 튀어 평균이 중앙값보다 훨씬 커지므로, 중앙값을 기준으로 봅니다.
- 구매의향 비율은 대부분 영상이 0%라 중앙값도 0%에 가깝습니다. 그래서 구매의향은 평균으로 비교합니다.
- 구독자 대비 조회수는 구독자가 매우 적은 채널에서 분모가 작아 값이 극단적으로 커지므로, 구독자 1,000명 이상 채널의 영상으로만 계산합니다. 다른 지표에는 모든 영상이 포함됩니다.

### 쇼츠 판정 기준

YouTube API에는 쇼츠 여부 필드가 없어서, YouTube 공식 기준을 길이와 화면 비율로 적용합니다.

- 정사각형 또는 세로 영상(높이 ≥ 너비)만 쇼츠입니다. 가로 영상은 길이와 상관없이 일반 영상입니다.
- 2024-10-15 이후 업로드: 180초 이하
- 2024-10-15 이전 업로드: 60초 이하
- 화면 비율은 `videos.list`의 `player.embedWidth/embedHeight`로 판단합니다.

### 콘텐츠 포맷 분류 (OpenAI)

영상의 제목·설명·해시태그를 바탕으로 포맷 하나를 고릅니다 (프롬프트 v3.1).

- 포맷: 챌린지 / 레시피·조리 / 먹방·ASMR·맛평가 / 기타
- 실제 음식이 아니라 종이·점토 등으로 만든 공예·모형 영상은 기타로 분류합니다. 이 규칙은 아래 1~3보다 먼저 적용합니다.
- 겹치면 위의 규칙이 우선합니다.
  1. 제목에 도전 구조(challenge, vs, 상금, 몇 입에)가 있으면 챌린지
  2. 만드는 과정이 중심이면 레시피·조리
  3. 먹거나 맛을 평가하는 영상이면 먹방·ASMR·맛평가
  4. 어디에도 안 맞으면 기타
- ASMR은 포맷이 아니라 연출 방식이라 독립 분류로 두지 않습니다.
- 출력은 JSON 스키마로 강제하고, 판단 근거 한 줄 → 포맷 → 확신도 순서로 답하게 합니다. 근거를 먼저 쓰게 하면 근거와 맞지 않는 포맷을 고르는 일이 줄어듭니다. 모델·프롬프트 버전·분류 시각을 함께 저장합니다.
- 영상마다 3번 분류해, 2번 이상 나온 포맷을 최종 포맷으로 정합니다. 3번이 모두 다르면 기타로 처리합니다. 회차별 결과도 따로 저장합니다.
- 3번의 결과가 모두 같지 않은 영상은 **경계 사례**로 표시합니다. 대시보드의 상위 영상 표에서 '경계 사례'와 '회차별 포맷' 열로 확인할 수 있습니다.
- 같은 프롬프트 버전으로 이미 분류한 영상은 다시 분류하지 않습니다.

### 기타와 종이 DIY

- 첫 분류에서 기타가 20%로, 포맷 목록을 다시 검토하는 기준(15%)을 넘어 기타 영상을 직접 확인했습니다.
- 종이로 만든 불닭 모형 영상이 19개 있었고, 이 영상들은 채널 5곳에 몰려 있었습니다. 이 중 2개는 '만드는 과정' 규칙에 걸려 레시피·조리로 잘못 분류되어 있었습니다.
- 종이 DIY를 새 포맷으로 만들면, 채널 몇 곳의 성과를 포맷의 성과로 오해할 수 있습니다. 그래서 새 포맷을 만들지 않고 분류 규칙(종이·점토 공예는 기타)을 보완해 다시 분류했습니다.
- 기타는 내용이 서로 다른 영상의 묶음이라 포맷 비교에서 제외합니다. 표에는 값을 보여 주되 '비교 제외'로 표시하고, 그래프에서는 뺍니다. 수집한 200개와 표의 '전체' 행에는 포함합니다.
- 최종 기타 60개의 구성: 종이 DIY 19 · 랭킹·모음 7 · 밈 6 · 판단 불가(제목·설명에 정보 부족) 23 · 그 외 5. 이 구성은 제목·설명·해시태그 규칙으로 센 참고 값이며, 대시보드의 데이터 기준 섹션에도 표시합니다.
- 재분류 후 기타는 60개(30%)로 기준을 넘지만, 늘어난 영상은 대부분 제목에 음식 이름만 있어 판단할 수 없는 영상(23개)이라 새 포맷을 만들지 않았습니다.

### 댓글 반응 분석 (YouTube + OpenAI)

- 영상별 관련도 상위 댓글 최대 20개를 수집합니다.
- 댓글 텍스트와 좋아요 수만 저장합니다. 작성자 정보는 저장하지 않고, 댓글 ID는 해시로, 본문의 @멘션은 `@user`로 바꿉니다.
- 댓글 하나씩 독립적으로 분류합니다.
  - 감성: 긍정 / 부정 / 중립
  - 구매의향: 있음 / 없음
- 영상별 비율을 먼저 구한 뒤 포맷별 평균과 중앙값을 냅니다. 분석 댓글이 5개 미만인 영상은 제외하고, 제외한 수를 표시합니다.
- 대시보드에는 집계 수치만 보여 주고 댓글 원문은 표시하지 않습니다.

### 3. 분류 안정성

- **일관성:** 같은 프롬프트로 3번 분류했을 때 3번 모두 같은 포맷이 나온 영상은 172개(86%)입니다. 이 숫자는 정확도가 아니라 일관성입니다. 같은 입력에 같은 답을 내는지를 본 것이고, 그 답이 맞는지는 따로 측정하지 않았습니다.
- **근거와 결과가 어긋난 분류:** 근거를 쓰고도 그와 맞지 않는 포맷을 고른 경우입니다(예: 근거는 "먹는 신호 없음"인데 결과는 먹방). 답하는 순서를 '포맷 → 근거'에서 '근거 → 포맷'으로 바꾼 뒤 200회 중 4건에서 600회 중 0건으로 줄었습니다. 문구 기준으로 찾은 사례라 놓친 것이 있을 수 있습니다.
- **경계 사례:** 28개를 빼고 계산해도 포맷 3개의 7개 지표 순위는 같았습니다.

### 4. 차이 검증 (부트스트랩)

포맷 간 차이가 우연인지 확인하기 위해, 영상을 다시 뽑아 지표를 계산하는 일을 1만 번 반복했습니다(부트스트랩). 두 가지 방식으로 확인했습니다.

- **영상 단위:** 포맷마다 영상을 다시 뽑습니다.
- **채널 단위:** 포맷마다 채널을 다시 뽑고, 뽑힌 채널의 영상을 모두 넣습니다. 같은 채널 영상끼리 비슷한 점을 반영합니다.

지표 7개 × 포맷 쌍 3개로 21번을 비교하므로, 차이가 없어도 우연히 걸리는 경우가 생길 수 있습니다. 그래서 21번 비교를 보정한 더 엄격한 구간(Bonferroni)에서도 0을 포함하지 않을 때만 "확실한 차이"로 봤습니다.

두 방식 모두에서 확실한 차이는 3개입니다.

- 조회수 속도: 챌린지 > 먹방·ASMR·맛평가
- 참여율: 먹방·ASMR·맛평가 > 레시피·조리
- 구매의향: 먹방·ASMR·맛평가 > 챌린지

구독자 대비 조회수는 레시피·조리가 가장 높지만(8.01), 95% 신뢰구간이 2.70~14.95로 넓어 1위라고 확실히 말하기 어렵습니다. 대시보드의 포맷 비교 그래프는 막대 높이로 순위를 매기지 않고, 막대에 마우스를 올리면 95% 신뢰구간을 보여 줍니다. 그래프마다 아래에는 채널 단위에서 확실한 차이가 있는 포맷 쌍만 적습니다. 확실한 차이가 없으면 "포맷 간 확실한 차이 없음"으로 표시하며, 현재 구독자 대비 조회수가 여기에 해당합니다.

### 5. 결과 분석

**① 챌린지는 빨리 퍼지고, 먹방은 반응과 구매 신호가 강합니다**
- 근거: 조회수 속도는 챌린지가 먹방의 약 3.7배입니다(34,860 대 9,445). 구매의향은 먹방이 챌린지보다 높고(5.6% 대 1.3%), 참여율은 먹방이 레시피보다 높습니다(2.84% 대 1.51%). 세 가지 모두 두 검증 방식에서 확실한 차이입니다.
- 제안: 한 캠페인 안에서 포맷의 역할을 나눌 수 있습니다. 빠르게 알리는 단계에는 챌린지, 구매 반응을 끌어내는 단계에는 먹방을 씁니다. 성과 지표도 챌린지는 조회수 속도로, 먹방은 참여율과 구매의향으로 따로 봐야 합니다.

**② 레시피는 긍정 반응이 높은 경향이 있지만, 아직 확실하지 않습니다**
- 근거: 긍정 비율은 레시피가 챌린지보다 높고(65.0% 대 43.7%), 구독자 대비 조회수도 가장 높습니다(8.01). 하지만 긍정 비율은 채널 단위 검증에서 우연일 수 있는 차이였고, 구독자 대비 조회수는 신뢰구간이 넓어 확실하지 않습니다.
- 제안: 레시피는 호감을 높이는 보조 포맷으로 검토할 수 있습니다. 결론으로 쓰려면 표본을 늘려 다시 확인해야 합니다.

**③ 챌린지의 부정 댓글은 대부분 제품 평가가 아닙니다**
- 근거: 부정 비율은 포맷 간 확실한 차이가 없었습니다. 챌린지 부정 댓글 20개를 직접 읽어 보니 제품에 대한 부정은 2개였고, 나머지는 출연자 놀림, 매운맛 리액션, 밈이었습니다.
- 제안: 부정 비율을 그대로 브랜드 리스크로 보고하면 잘못된 판단을 할 수 있습니다. 감성은 대상(제품 · 출연자 · 연출)을 나눠 봐야 합니다.

위 내용은 관찰 데이터에서 나온 결과라 인과가 아닙니다. 포맷과 함께 크리에이터의 영향도 섞여 있을 수 있습니다. 확인하려면 같은 크리에이터가 포맷만 바꿔 만드는 식의 실험이 필요합니다.

## 한계

- **표본 편향**: `buldak` 검색의 관련도 상위 영상만 봅니다. 무작위 표본이 아니어서 성과가 좋은 영상 쪽으로 치우쳐 있을 수 있습니다.
- **표본 크기**: 포맷당 영상이 40~50개로 적어, 포맷 간 차이 중 확실하다고 말할 수 있는 것은 일부(21개 비교 중 3개)뿐입니다.
- **데이터 범위**: 공유 수·시청 시간·비용·전환은 YouTube Data API가 제공하지 않아 포함하지 않았습니다. 광고 조회수와 자연 조회수도 구분할 수 없습니다.
- **크리에이터 표의 영상 수**: 이번 검색에 잡힌 영상 수이며, 채널 전체 영상 수가 아닙니다.
- **쇼츠 판정 방식**: 화면 비율을 임베드 크기로 판단해 실제 영상 비율과 조금 다를 수 있습니다.
- **LLM 포맷 분류의 한계**: 영상 내용을 보지 않고 제목·설명·해시태그로만 분류합니다. 전체 200개 중 23개(11.5%)는 제목·설명에 정보가 부족해 판단할 수 없었습니다. 또 "제목에 도전 구조가 있으면 챌린지" 규칙과 달리 설명의 #challenge만 보고 챌린지로 분류한 영상이 4개 있습니다. 정확도는 따로 측정하지 않았습니다.
- **댓글 표본의 한계**: 영상별 관련도 상위 20개만 분석했습니다. 댓글 작성자는 시청자 일부이고, 구매의향 댓글이 실제 구매로 이어졌는지는 알 수 없습니다.
- **감성 대상 미구분**: 감성은 댓글 전체 분위기 기준이라 제품·출연자·연출 중 무엇에 대한 반응인지 나누지 않습니다(결과 요약 2의 부정 댓글 검토 참고).

## 실행 방법

Python 3.10 이상에서 실행합니다.

```bash
python -m venv venv
venv\Scripts\python.exe -m pip install -r requirements.txt     # macOS/Linux: venv/bin/python
```

프로젝트 폴더에 `.env` 파일을 만들고 API 키를 넣습니다. 이 파일은 git에서 제외됩니다. OpenAI 키가 없으면 포맷 분류만 건너뜁니다.

```
YOUTUBE_API_KEY=발급받은_키
OPENAI_API_KEY=발급받은_키
```

```bash
venv\Scripts\python.exe -m streamlit run dashboard.py   # 대시보드 (데이터가 없으면 열 때 자동 수집)
venv\Scripts\python.exe collect.py search               # 명령줄에서 직접 수집
venv\Scripts\python.exe collect.py refresh              # 저장된 쇼츠의 지표만 갱신 (약 10유닛)
venv\Scripts\python.exe collect.py purge                # 30일 지난 데이터 삭제
venv\Scripts\python.exe classify_formats.py             # 미분류 쇼츠의 포맷 분류 (OpenAI)
venv\Scripts\python.exe collect_comments.py             # 새 영상의 상위 댓글 수집 (영상당 1유닛)
venv\Scripts\python.exe classify_comments.py            # 새 댓글의 감성·구매의향 분류 (OpenAI)
venv\Scripts\python.exe -m pytest tests                 # 테스트
```

- 로컬에서 자동 수집을 끄려면 환경변수 `AUTO_COLLECT=0`을 설정합니다.
- API 키를 읽는 순서는 환경변수(`.env` 포함), 그다음 Streamlit Secrets입니다. 키 값은 화면이나 로그에 출력하지 않고, 오류 메시지에 섞이면 `***`로 가립니다.

### Streamlit Community Cloud 배포

1. 이 저장소로 새 앱을 만들고 Main file을 `dashboard.py`로 지정합니다.
2. Advanced settings → Secrets에 다음을 입력합니다. 배포 앱은 스냅샷만 보여 주므로 YouTube·OpenAI 키는 넣지 않습니다.
   ```toml
   SNAPSHOT_MODE = "1"
   DATA_REPO = "소유자/스냅샷_저장소_이름"
   DATA_TOKEN = "발급받은_토큰"
   ```
3. `DATA_TOKEN`은 스냅샷 저장소 하나에 Contents 읽기 권한만 준 fine-grained 토큰을 권장합니다.
4. 스냅샷은 로컬에서 `venv\Scripts\python.exe make_snapshot.py`로 만들고(`data/snapshot/`), `shorts_snapshot.db`와 `snapshot.json`을 비공개 저장소에 올립니다.

├── collect.py          # YouTube API 수집 (search / refresh / reclassify / purge)

└── data/               # SQLite DB (git 제외, 실행 시 생성)
